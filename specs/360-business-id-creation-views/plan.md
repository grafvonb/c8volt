# Implementation Plan: Business-ID Creation and Complete Resource Views

**Branch**: `360-business-id-creation-views` | **Date**: 2026-10-31 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/360-business-id-creation-views/spec.md`

## Summary

Add optional business IDs to creation inputs and observed process, job, task, listener, and slow-analysis data. Extend `run pi` with `--bid` for both definition selectors, enforce the supported backend's 256 UTF-16-unit limit, and reject this capability in 8.8/8.9 adapters without changing default configuration. Use native v810 fields already present in generated clients.

Carry IDs through both directions of facade conversion, observed previews, special renderers, and saved reports. Preserve each resource's own backend snapshot. Repair the existing sequential/count creation result-loss chain so successful items survive later failures through one error envelope and the original exit status. Keep backend mechanics in internal services and human mutation output in configured logging. Research is complete in [research.md](research.md).

## Technical Context

**Language/Version**: Go 1.26.0; toolchain go1.26.2 from `go.mod`.

**Primary Dependencies**: Existing Cobra 1.10.2, pflag 1.0.10, Viper 1.21.0, generated Camunda clients, Go Unicode/JSON/logging facilities, `toolx` pointer helpers, `toolx/pool`, and existing facade error conversion. No new dependency or client regeneration expected.

**Storage**: Invocation-local models and existing report files; Camunda remains authoritative. No database, index, migration, or ID registry.

**Testing**: Go/testify, generated-client mocks, test-owned HTTP servers, isolated command subprocesses and real-terminal fixtures. Planning changes receive document checks only.

**Target Platform**: Existing CLI/library platforms; native support in v810, explicit unsupported creation input in v88/v89. Terminal tests retain supported-platform behavior and report skips.

**Project Type**: CLI plus public Go facade library with versioned internal services.

**Performance Goals**: O(length of ID) validation, bounded at 256 UTF-16 units; O(number of already returned resources) mechanical copying/rendering. No additional requests solely for ID display, no uniqueness discovery, unchanged creation worker limits and polling policy. No invented latency SLA.

**Constraints**: Opaque values, optional presence, resource-specific snapshots, stable envelopes and enrichment shapes, no-wait acceptance distinguished from observed creation, partial results plus original errors, logger/stream compliance, no live implementation validation.

**Scale/Scope**: Three existing creation entry points, two native payload variants, three version adapters for input policy, five public resource areas, all eleven specification view/report groups, and existing counted creation. Filtering/resolution, late assignment, atomic job-completion assignment, new command families, and generic capability frameworks remain excluded.

## Phase 1 — Design

### Input and version policy

Use a scalar `--bid` and flag presence to construct a copied optional `BusinessId` in every creation input. CLI parsing must preserve explicit-empty input; authoritative capability and value validation belong below the public facade so older versions retain unsupported classification for every supplied ID. Add a small domain validator for valid UTF-8, nonempty value, and at most 256 UTF-16 code units. Do not import internal domain mechanics into the CLI or duplicate backend orchestration there.

v88/v89 reject any non-nil creation input with the existing unsupported class at adapter entry. v810 validates before native request construction. Bulk services snapshot business-ID input before scheduling and retain existing selector/count/worker policy. They do not perform version-neutral value validation ahead of the adapter: older adapters reject capability first, while v810 validates each attempt before mutation. Invalid counted input still causes zero mutation requests. Both by-ID and by-key payloads set the field directly. No suffixes, client uniqueness check, new retry policy, or default-version change.

### Data propagation and ownership

Use the explicit type/conversion inventory in [data-model.md](data-model.md). Add corresponding domain/public fields together, copying pointer values at mutable boundaries. Leave older observation mapping unchanged. Cover the duplicated operations process mapper, all listener facades, slow-analysis root mapping, completion candidate reconstruction and plan snapshots, and custom dry-run/Markdown representations.

Preserve nil even when a related instance or supplied creation input has an ID. Ordinary waiting maps the ID from the observed instance rather than keeping an obsolete creation-response value. Do not change listener section pointers, variable wrappers, or query result shapes. No extra reads for key/status-only output or local previews.

### Partial creation and error flow

Preserve accumulated items in `internal/services/processinstance.CreateProcessInstances` on a later failure. For counted creation, keep existing pool execution but compact only successful results using per-worker completion evidence; zero-value slots must not become empty resources or keys. Preserve ordering and existing fail-fast/cancellation behavior. Map these partial slices even when an error exists in both public creation collection methods.

Trace the final path explicitly: adapter error and successful sibling observations → service partial slice plus original error → facade converts both → command attaches tenant evidence and renders existing payload → JSON emits one failure envelope, or human/keys render permitted partial results → non-JSON emits one bounded configured ERROR → `exitAfterRenderedResult` preserves the original class and `NoErrCodes` behavior. No second `handleCommandError` after a rendered envelope. Rendering errors must not cause duplicate output or override an existing operation error's exit classification.

No-wait success retains accepted semantics; partial failure remains a failure even with no-wait. A failed wait is not converted to successful creation evidence for that item. This feature preserves successful siblings without redesigning uncertain native submission tracking.

### Views, logging, and reports

The [resource-view contract](contracts/resource-views.md) is the complete implementation coverage matrix. Show a compact `bid:<value>` field only when present, beside the process name in process-instance rows; quote empty values and values containing characters other than letters, digits, or `-_.@/:`; preserve compact summaries and escape control characters. JSON retains exact strings. Saved Markdown uses escaped values in existing observed resource lists without leaking raw markup.

Move the touched creation result and flat-row functions from the command into `cmd/cmd_views_processinstance_run.go`. Human mutation rows/summaries and verbose output use `renderHumanLine` with the configured command logger; query rows and machine results remain stdout. Keep plain prompts on configured stderr. Preserve quiet/WARN suppression, activity behavior, inherited destinations, plain/structured formats, and existing output-mode precedence.

Group repeated human failure causes into bounded aggregate diagnostics using established job/process logging patterns; report only counts supported by actual evidence. Do not classify unattempted work as backend rejection. Raw error evidence stays in established machine schemas and redacted DEBUG paths; verbose alone never enables HTTP diagnostics.

### Compatibility and documentation

Absent business IDs preserve old JSON and older-version functionality. Optional public fields are additive for keyed literals; document possible source adjustments for unkeyed external literals. Human creation output intentionally moves to configured INFO logging as required by repository policy; document that stream correction. Preserve aliases, selector combinations, tenant rules, wait states, envelope shape, totals, and keys-only semantics.

Update command metadata, `run` guidance where relevant, README, examples, and output documentation in the same implementation units as the behavior. Explain UTF-16 units with a short Unicode example, supported version, repeated-count uniqueness, and no-wait. Regenerate CLI docs with `make docs-content`; do not hand-edit generated files. Existing scopes without observed IDs remain read-free.

## Validation Strategy

[quickstart.md](quickstart.md) gives executable isolated checks for implementation. Planning validates documents only.

- Unit/round-trip checks cover all optional fields, nil and empty observed values, pointer isolation, independent parent/resource IDs, and frozen completion candidates.
- Native tests use generated request serialization against owned HTTP fixtures for both selectors, supplied/omitted fields, Unicode boundaries, old-version rejection before mutation, and response/wait differences.
- Service/facade checks cover successful prefixes, counted mixed outcomes, zero-slot compaction, ordering, worker bounds, fail-fast/cancellation, and original errors alongside partial results.
- Command checks cover creation and all table surfaces, every supported output mode, empty/no-op paths, sparse discovery continuation, exact-key previews, request counts, report-file content, and no extra lookups.
- Diagnostic tests exercise real command execution, repeated raw backend failures, separate streams, configured/inherited destinations, both logger formats, quiet/WARN, both DEBUG entry points/redaction, exact envelope EOF, and original exit codes. Tests must fail for direct-print substitutions and normal-level raw errors.
- Use real terminal stdin for affected prompt and empty-scope paths; preserve approve/decline/EOF and redirected output behavior. Report platform skips accurately.
- Run targeted tests first and the repository race suite once after the shared cross-package changes pass. No repeated full suite for subsequent prose-only edits. No live tests, target discovery, cluster inspection, provisioning, or cleanup gates.
