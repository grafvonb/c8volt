## Maintenance Rules

- Add a row when a real-state scenario cannot prove a required behavior because a setup command or embedded BPMN asset is missing.
- Remove or update a row only after the corresponding runtime test proves the behavior against real Camunda state.
- Keep the runtime-test behavior column honest: skipped, dry-run-covered, partially live-covered, or live-covered.
- Keep future Camunda minor releases as additional rows or explicit scope updates rather than changing the 8.9 foundation silently.
- Use the `Affected Versions` column for the current 8.9 foundation and add explicit new rows or comma-separated minors when later Camunda releases need different setup or assertions.
