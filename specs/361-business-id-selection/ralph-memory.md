## Gotchas

- Resolution fail-fast retains its existing process-instance scheduling boundary: finish all reviewed incidents inside an already-running PI, then stop scheduling further PIs. Do not break the per-incident loop on FailFast; only context interruption stops that loop. `TestBusinessIDResolveFailFastFinishesInstance` guards this.
- The incident adapter still applies its established configured tenant filter to scoped incident reads, even after key-authorized PI-family expansion. Native tenant equality serializes as a scalar. Direct service constructors expect the configured API URL to include `/v2`; command test configuration already does so.
- BID resolution uses a dedicated lifecycle/view, never the legacy raw per-instance error renderer. Nonempty JSON retains existing result fields plus `plan`; completed empty selection uses the unchanged resolution summary. Keys-only emits PIs with planned/confirmed/submitted incident work, no skipped/no-op keys. Human failures explicitly retain incomplete accepted submissions. Real-terminal confirmation wording stays unchanged; all incident reads finish before the question.

- BID variable-update approval must call the mode-aware `renderUpdateProcessInstanceVariablePlan`; directly invoking its human helper prints an unwanted INFO preview before a keys-only prompt. `TestBusinessIDActionsKeysConfirmation` reproduces that violation with real terminal stdin and requires exact plain prompt stderr plus accepted-key stdout.
- State-control BID default scope remains exact, including terminal/ineligible observations; only `--tree` applies observed ACTIVE/SUSPENDED eligibility. Use original discovery options when consuming selected plans, not `collectExplicitPIAdminInputOptions`. Empty scopes bypass keyed no-input failures only after completed discovery. `--limit`/`--batch-size` without BID fail instead of being silently ignored.

- The native v810 delete endpoint is `POST /v2/process-instances/{key}/deletion`. The shared command fixture now records deletion attempts separately from accepted deletions, so failed conflicts do not falsely make subsequent cancellation prechecks see absence. Setting `afterApproval` exposes a new child to any accidental rediscovery; frozen deletion tests require no delete for it and preserve the root conflict.
- Human partial deletion counts distinguish `submitted members` under no-wait from `deleted members` after confirmation. Accepted-but-failed absence waits retain a bounded unconfirmed-submission diagnostic. Never infer no submission just because every root failed: children or prerequisite cancellation may already have been accepted.

- The confirmation helper renders its final question on a new line: use `...will be canceled.\nDo you want to proceed? [y/N]: ` in PTY exchanges. `runBusinessIDCommand` now accepts optional terminal exchanges and still rejects configured-stream bypasses. Automation empty human output preserves existing INFO `found: 0`; quiet and keys-only suppress it.
- Cancel does not register `--pd-key`; combined native predicate fixtures use its existing `--bpmn-process-id`, state and date flags. Normal human failures must use `formatBusinessIDCancellationFailure`, never raw report.Status or joined errors. Semantic per-key callbacks are deliberately absent from this lifecycle; configured summary rendering owns diagnostics, and HTTP DEBUG remains available independently.

- Walk no longer marks `--key` unconditionally required: key-or-BID validation runs after bootstrap for configured diagnostics/one JSON envelope. Enrichment validators accept BID but retain their established output incompatibilities. Keep required-key metadata assertions aligned; use isolated subprocesses for no-selector errors because the command exits.
- The shared envelope success spelling is `succeeded`, with result data under `payload`. Listener enrichment can query `/v2/jobs/search` even with no element rows. Use owned fixture responses with authoritative empty page metadata.

- v810 PI search serializes `processInstanceFilter`, not the generated filter directly; update its fields and `isEmpty()` together. Both facade process/ops conversion directions must copy BID.
- Native variable equality is serialized as a `$eq` object, even though BID is a scalar. Variable/effective-variable empty fixtures need `hasMoreTotalItems:false` as well as `totalItems:0`.
- Cobra Args validation precedes command logger/bootstrap. For new BID user-task input, defer validation to Run before stdin or native requests so invalid JSON yields exactly one envelope; legacy omitted-BID validation behavior stays intact.

- The current query quiet mode retains nonempty ordinary rows; empty human summaries are suppressed. Do not silently change this while adding BID.
- Existing capped-total tests had terminal empty pages still promising 10,000 matches. Their terminal estimates now reconcile to the three observed results; rejecting contradictory terminal metadata is intentional.
- Repeated offset page signatures and repeated/cyclic cursors fail incomplete. A zero-item selected page with valid continuation must keep going.
- Public struct fields are additive but unkeyed literals need updating; custom facade implementations must explicitly supply completion before later selection consumers trust them. README documents this.
- `runBusinessIDCommand` in the command tests is reusable for actual root execution with real terminal stdin, separate streams, configured/inherited logger destinations and original exit codes, despite its feature-specific name.
